Docs / Tutorial

Your first match

You will make a game, change it while it runs, turn it into a team deathmatch, and join it from a second window the way a friend on your network would.

  • About ten minutesafter a one-off install that takes about five more
  • Linux or Windowswith a graphics driver from the last few years
  • No experience neededevery command is here to copy

What you get today

FOSSPS is early. At the end of this page two players stand in the same world and walk around it, on teams, with a round running. The world is a test floor with a few blocks, other players are not drawn yet, and nobody can shoot anybody: weapons in a running match are still being built. The engine plays a pretend match against your rules instead, and you will watch it do that in step 5.

Steps

  1. Install FOSSPS
  2. Make a game
  3. Play it
  4. Change it while it runs
  5. Turn it into a team deathmatch
  6. Start a server
  7. Join the match

1Install FOSSPS

There is no download yet, so your computer builds FOSSPS from its source code. That needs two things installed first, and you only do this once.

Everything on this page is typed into a terminal. On Linux, open the program called Terminal or Konsole. On Windows, press the Windows key, type PowerShell and press Enter.

Rust, which builds the engine

Follow the one step at rustup.rs, then close the terminal and open a new one. On Windows it also offers to install the Visual Studio build tools: say yes.

On Linux only: a compiler and two libraries

Ubuntu, Debian, Mint 
sudo apt install g++ libudev-dev libasound2-dev
Fedora 
sudo dnf install gcc-c++ systemd-devel alsa-lib-devel

FOSSPS itself

cargo install --git https://github.com/tahuffman1s/FOSSPS fossps

This is the slow part: one to five minutes on most computers, longer on an old one. Lines starting with Compiling scroll past while it works. Nothing is wrong while they keep coming.

You should see

The last line starts with Installed package. Check that the command is there:

fossps --version
fossps 0.0.0
It says cargo is not found, or fossps is not found

The terminal was open before Rust was installed. Close it, open a new one and try again.

It stops with linker `cc` not found or failed to run custom build command

A compiler or library is missing. On Linux, run the line for your system under “a compiler and two libraries” above. On Windows, run the Rust installer again and let it install the Visual Studio build tools. Then run the cargo install line again; it carries on from where it stopped.

2Make a game

fossps new first-match

You should see

Created the game "first-match" in …

Play it:
    cd first-match
    fossps run

Then open main.luau in an editor, change something and save: the running game updates by itself.

A game is a folder. Yours is called first-match, and the file that matters in it is main.luau: the game's script. Go into the folder, and stay in it for the rest of this page:

cd first-match

3Play it

fossps run

You should see

A window opens on a chequered floor with a few blocks standing on it. The terminal says, among a few other lines:

[INFO] Playing ./main.luau. Edit the file and save it to see changes right away.
[INFO] Welcome to first-match! Click the game window so it can see your mouse.
[INFO] Jump: Space, or the bottom face button on a gamepad.
[INFO] Fire: left mouse button, or the right trigger.

On Windows the first line says .\main.luau. Click the window, then look around with the mouse and walk with W A S D. A gamepad works too: left stick to walk, right stick to look. Press Space a few times and watch the terminal:

[INFO] Jump number 1
[INFO] Jump number 2

That text comes from your script. Esc gives the mouse back. Leave the game running for the next step.

It says Could not find Vulkan on this computer, or that Vulkan is too old

FOSSPS draws with Vulkan 1.3, which comes with the graphics driver. Update the driver for your graphics card and run fossps run again. On Linux, also install the Vulkan loader: sudo apt install libvulkan1 or sudo dnf install vulkan-loader.

It says There is no game here

The terminal is not in the game's folder. Run cd first-match, then fossps run again.

4Change it while it runs

Open first-match/main.luau in any text editor: Notepad and Text Editor are fine. Find this line:

        print("Jump number " .. saved.jumps)

Change the words inside the quotes, and save the file:

        print("Boing! That is jump " .. saved.jumps)

You should see

The terminal says the game took the new version, without restarting. If you had jumped twice:

[INFO] Reloaded main.luau.
[INFO] main.luau was saved and loaded again. Jumps so far: 2

Jump in the game, and the terminal carries on counting: Boing! That is jump 3. The count was not lost because the script keeps it in a game.keep table; everything else in the file starts over on a save.

Now break it on purpose. Change game.onTick to game.onTik and save:

[ERROR] Script error in main.luau, line 22:

    22 | game.onTik(function(step)

  game.onTik does not exist. Did you mean game.onTick?
  The game keeps running the last version that worked. Fix this and save the file: it reloads by itself.

The game did not crash, and the message says which line and what to try. Put the c back, save, and it reloads. Then close the game's window.

5Turn it into a team deathmatch

Replace everything in main.luau with this, and save:

main.luau 
-- first-match: a team deathmatch.

-- This one call is the whole game mode. The engine shares players out over
-- the teams, scores a point for killing an enemy, brings the dead back, and
-- starts and ends the rounds. timeLimit is in seconds.
game.mode {
    teams = { "Red", "Blue" },
    scoreToWin = 50,
    timeLimit = 600,
}

-- Everything below is a rule of your own. print() writes to the terminal.

game.onPlayerJoin(function(player)
    print(player.name .. " joined " .. player.team.name .. ".")
end)

game.onRoundStart(function()
    print("The round is on! First team to 50 wins.")
end)

game.onKill(function(killer, victim)
    if killer and killer.team ~= victim.team then
        print(killer.name .. " scored for " .. killer.team.name .. ".")
    end
end)

game.onRoundEnd(function(winner)
    if winner then
        print(winner.name .. " wins the round!")
    end
end)

Nobody can score in a running match yet, so let the engine try your rules out. This command opens no window: it plays a short pretend match with two bots and tells you if anything in the script went wrong.

fossps check

You should see

[INFO] Check Bot 1 joined Red.
[INFO] Check Bot 2 joined Blue.
[INFO] The round is on! First team to 50 wins.
[INFO] Check Bot 1 scored for Red.
[INFO] Red wins the round!
main.luau is fine: it loaded and ran for 60 ticks (1 second of game time) with no errors.

A few more lines follow, saying what the pretend match did and did not try.

Each of those lines is one of your print calls, run by the engine at the moment its rule applied.

It says main.luau has a mistake

Something went missing when the script was pasted. The lines above that message name the line and what to try. Select everything in main.luau, paste the script again, save, and run fossps check again.

6Start a server

In a multiplayer shooter one program, the server, decides what happens, and every player connects to it. Start one for your game:

fossps serve

You should see

[INFO] Serving ./main.luau at 60 ticks a second, with no window. Press Ctrl-C to stop.
[INFO] Players on this network join with just `fossps join`, which finds this game by itself, or by address: …

Then it waits. No window opens: a server only keeps the match. (On Windows the first line says .\main.luau.)

Leave it running in this terminal.

It says The server could not start

Another server is already running on this computer, probably in another terminal. Stop that one with Ctrl+C, or do what the message says to use another port.

A firewall asks whether to allow fossps

Allow it on private networks. Without that, players on other computers cannot reach your server; joining from the same computer works either way.

7Join the match

Open a second terminal and run this. It does not need to be in the game's folder:

fossps join

You should see

A window opens on the same floor, and the second terminal says:

[INFO] Looking for games on this network...
[INFO] Found first-match (0 of 64 players).
[INFO] Joining localhost...
[INFO] Joined as Player 1. Close the window to leave.

Look back at the first terminal. The server saw you arrive and your own rules ran on it; the first line is the server's, the next two are yours, and the last comes after a five-second warm-up:

[INFO] Player 1 joined from …
[INFO] Player 1 joined Red.
[INFO] The round is on! First team to 50 wins.

That is a networked match: the server holds the teams, the score and the clock, and you are a player in it. Notice that fossps join was given no address. It found the game by itself, and it does the same from any other computer on your network that has FOSSPS installed. Try it with a friend: they will be Player 2, on Blue.

Close the window to leave, and press Ctrl+C in the first terminal to stop the server.

It says No games were found on this network

Check that the first terminal still shows the server running. From another computer, a firewall or a guest Wi-Fi network can hide the server: use the address the server printed when it started, as in fossps join 192.168.1.20.
